# GameMind AI - Release Hardening Plan

Этот документ содержит подтверждённый список проблем, уязвимостей и архитектурных недостатков, которые необходимо исправить перед открытым beta-релизом.

## 🔴 PHASE 1 — CRITICAL SECURITY

### [ ] AI-01: Вшитые ключи AI API (Embedded AI Keys)
* **Severity:** CRITICAL
* **Название:** Хардкод ключей Gemini и Groq в клиентском приложении
* **Описание:** В исходном коде (`.env` и `ai.client.ts`) присутствуют ключи `BUILTIN_GEMINI_KEY` и `BUILTIN_GROQ_KEY`. Приложение использует их как fallback. Это приведет к их утечке через Electron asar bundle и исчерпанию лимитов API.
* **Затронутые файлы:** `src/main/services/ai/ai.client.ts`, `.env`, `.env.example`, `electron.vite.config.mts`
* **Затронутые системы:** AI Client, Electron Main
* **Потенциальный impact:** Финансовые потери, полная блокировка AI функций для всех пользователей.
* **Статус:** [x] RESOLVED
* **Зависимости:** Нет
* **Способ проверки:** Поиск `BUILTIN_` по всему проекту. Запуск приложения без пользовательского ключа (должна корректно отработать заглушка/ошибка).
* **Требует Supabase изменения:** Нет
* **Требует ручного действия:** Нет

### [x] SEC-01: Подделка прав Администратора (Boss / RBAC)
* **Severity:** CRITICAL
* **Название:** Клиентская валидация прав Boss
* **Описание:** Права администратора (например, для блокировки) проверяются на фронтенде (`isBoss`) на основе наличия значка `boss` или `username`. Злоумышленник может обойти это ограничение. Бейдж используется как security boundary.
* **Затронутые файлы:** `src/renderer/src/features/profile/UserProfilePage.tsx`, `src/main/ipc/handlers/*`
* **Затронутые системы:** Frontend, IPC, БД
* **Потенциальный impact:** Неавторизованный доступ к админским функциям.
* **Статус:** [x] RESOLVED
* **Зависимости:** SEC-04 (Badges)
* **Способ проверки:** Попытка вызвать защищенный IPC или Supabase RPC без админских прав.
* **Требует Supabase изменения:** Да (Добавление проверки ролей или JWT claims).
* **Требует ручного действия:** Да

### [x] SEC-02: Утечка приватных данных профиля (Profile RLS Bypass)
* **Severity:** CRITICAL
* **Название:** Открытый SELECT на таблице `users`
* **Описание:** Текущая политика RLS (`USING (true)`) позволяет любому авторизованному пользователю загрузить `dna_summary`, скрытые игры и настройки любого профиля. Приватность соблюдается только визуально на UI.
* **Затронутые файлы:** `supabase/rls-policies.sql` (и миграции)
* **Затронутые системы:** Supabase RLS, Profile
* **Потенциальный impact:** Слив чужих приватных данных и скрытых профилей (Data Leak).
* **Статус:** [x] RESOLVED
* **Зависимости:** Нет
* **Способ проверки:** Выполнение прямого REST API запроса к `users` от лица User B для чтения приватных данных User A.
* **Требует Supabase изменения:** Да (SQL migration).
* **Требует ручного действия:** Да

### [x] SEC-03: Подделка сообщений и спам (Chat RLS & Permissions)
* **Severity:** CRITICAL
* **Название:** Отсутствие защиты содержимого чатов
* **Описание:** Политики RLS на таблице `messages` позволяют получателю менять `content` сообщения (`UPDATE` без ограничений колонок). `INSERT` политика позволяет кому угодно писать кому угодно, игнорируя параметр `chat_privacy` получателя.
* **Затронутые файлы:** `supabase/dm-migration.sql`, `supabase/chat-improvements.sql`
* **Затронутые системы:** Supabase RLS, Messages Service
* **Потенциальный impact:** Подделка переписок (Social Engineering), массовый спам.
* **Статус:** [x] RESOLVED
* **Зависимости:** Нет
* **Способ проверки:** Попытка изменить текст чужого входящего сообщения через REST API; попытка отправить сообщение пользователю с `friends_only`.
* **Требует Supabase изменения:** Да (SQL migration).
* **Требует ручного действия:** Да

### [x] SEC-04: Неавторизованная выдача значков (Badge Security)
* **Severity:** HIGH
* **Название:** Прямой клиентский INSERT в `user_badges`
* **Описание:** Клиентское приложение напрямую делает `.upsert()` в `user_badges` для выдачи значков (включая Boss). Отсутствуют RLS ограничения, предотвращающие самовольную выдачу бейджей.
* **Затронутые файлы:** `src/renderer/src/features/badges/hooks/useBadges.ts`, `src/main/services/badges.service.ts`
* **Затронутые системы:** Supabase RLS, Badges System
* **Потенциальный impact:** Любой пользователь может выдать себе любой значок, обесценивая систему.
* **Статус:** [x] RESOLVED
* **Зависимости:** Нет
* **Способ проверки:** Прямой запрос к Supabase на добавление редкого бейджа.
* **Требует Supabase изменения:** Да (SQL migration, RLS или RPC).
* **Требует ручного действия:** Да

### [x] SEC-05: Авторизация в чувствительных IPC-хендлерах (Sensitive IPC)
* **Severity:** HIGH
* **Название:** Отсутствие валидации прав в IPC
* **Описание:** Некоторые IPC хендлеры (например, `JOURNAL_ADMIN_GENERATE`, `JOURNAL_ADMIN_DELETE`) безоговорочно выполняют локальные деструктивные действия по запросу из renderer.
* **Затронутые файлы:** `src/main/ipc/handlers/journal.ipc.ts` и другие
* **Затронутые системы:** Electron IPC
* **Потенциальный impact:** Злоумышленник, выполнив XSS в renderer, может удалить локальную БД или журналы.
* **Статус:** [x] RESOLVED
* **Зависимости:** Нет
* **Способ проверки:** Вызов `window.api.journal.adminDelete()` из консоли DevTools обычным юзером.
* **Требует Supabase изменения:** Нет
* **Требует ручного действия:** Нет

## 🟠 PHASE 2 — DATA INTEGRITY & ARCHITECTURE

### [ ] DATA-01: SQLite ↔ Supabase Sync конфликты и потери (Data Sync)
* **Severity:** HIGH
* **Название:** Утеря данных при сбое синхронизации
* **Описание:** `SyncEngine` при смене аккаунта удаляет все локальные данные. Если после этого облачная синхронизация падает (отсутствие интернета/таймаут), пользователь останется с пустой БД без возможности восстановления из локального кэша. Также возможны race conditions при параллельных записях.
* **Затронутые файлы:** `src/main/services/steam/sync-engine.ts`, `src/main/services/cloud-sync.service.ts`
* **Затронутые системы:** SQLite, Supabase Sync
* **Потенциальный impact:** Потеря локальных достижений, истории и ДНК.
* **Статус:** [ ] OPEN
* **Зависимости:** Нет
* **Способ проверки:** Имитация обрыва сети во время синхронизации (отключение интерфейса).
* **Требует Supabase изменения:** Нет
* **Требует ручного действия:** Нет

### [ ] ARCH-01: Утечки Supabase Realtime (Realtime Cleanup)
* **Severity:** MEDIUM
* **Название:** Избыточные подписки и отсутствие cleanup
* **Описание:** Компоненты (напр. `GlobalRealtimeListener`, `ChatsPage`) подписываются на изменения таблиц. Отсутствие строгого контроля может привести к duplicate subscriptions. Бесплатный лимит Supabase (200 коннектов) будет быстро исчерпан.
* **Затронутые файлы:** `src/renderer/src/components/GlobalRealtimeListener.tsx`, `ChatsPage.tsx` и др.
* **Затронутые системы:** Frontend React, Supabase Realtime
* **Потенциальный impact:** Отключение Realtime для всех пользователей по превышению лимитов провайдера, утечки памяти на клиенте.
* **Статус:** [ ] OPEN
* **Зависимости:** Нет
* **Способ проверки:** Навигация между страницами чата с мониторингом открытых веб-сокетов и активных channels в Supabase Dashboard.
* **Требует Supabase изменения:** Нет
* **Требует ручного действия:** Нет
